## 2024-11-23 - Kotlin Constructor Delegation & State-Preserving Clones
**Learning:** In the Root Chess Android codebase, `Board.clone()` is a hot path called frequently during move generation, AI simulations, and UI rendering state updates. The standard `Board` constructor automatically calls `resetBoard()` inside an `init` block (allocating 64 `Spot`s and 32 `ChessPiece`s). This results in redundant garbage collection and CPU overhead when a cloned board overwrites the `boxes` field. Additionally, unlike standard chess models, all `ChessPiece` subclasses (even `Knight`, `Bishop`, `Queen`) have `hasMoved` and `canEnPassant` in their constructor signatures in this codebase to align with the base class.
**Action:** Bypass standard initialization during deep copying by using Kotlin's constructor delegation (supplying an optional parameter `initialBoxes` to bypass `resetBoard()`). When replicating chess pieces inside `clone()`, explicitly pass named parameters like `hasMoved = piece.hasMoved, canEnPassant = piece.canEnPassant` to preserve game-state logic (e.g., castling, en passant) across cloned boards.
