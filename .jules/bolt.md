## 2024-10-25 - Eliminating Redundant Game Board Cloning and Lookup Allocations
**Learning:** In turn-based board games (like Chess) with frequent AI evaluation, cloning and deep-copying boards is a frequent operation. In Kotlin, initializers and `init` blocks run before secondary constructors. Creating a Board instance with default initializers (`resetBoard()`) and then overwriting its state during cloning leads to excessive allocations (64 Spots and 32 ChessPieces per clone). Using a primary constructor pattern with nullable parameters bypasses this overhead completely. Hoisting invariant lookups (like target spots in check detection) and using direct 2D list indexing instead of getter methods removes bounds-checking overhead inside hot nested loops.
**Action:** When designing data models that require deep cloning or state snapshotting, always provide a way to pass the cloned state directly into the constructor to bypass default initialization.
